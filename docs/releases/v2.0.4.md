Ring++ 2.0.4 -- a native library's handle dies with its object, and `not` binds as Ring's does.

**A handle an engine library gave you stops being valid when the library frees the object.** On Ring a C pointer that a
native returns is a value every copy keeps after the owner frees it, and Ring++ carried the raw address in a number,
which kept the same property across libraries: a copy of a destroyed engine object read freed memory. The host keeps
one handle table now, offered to the libraries (ABI 3). A handle is an id with a generation; freeing the object makes
every copy of the id stale, so a read through a copy answers nothing, and freeing twice is ignored. An id means the
same in every engine library. On a real handle -- Softanza's `StzEngineString`, copied, freed, then read through the
copy -- the 2.0.3 packages fail with a panic on Windows and a general protection fault on Linux, and these answer an
empty string. An engine built for an older host still loads and keeps its old handles; one built for a later host is
refused by name. Both packages ship engines built for this one (89 libraries on Windows, 87 on Linux). It costs a
mutex round per handle operation: a round of create, use and free of an engine object took 107 ns and takes 143.

**`not` is read as Ring reads it.** Ring binds `not` below every comparison and arithmetic operator and above `and` and
`or`; the grammar Ring++ parses with binds it like a unary minus. So `not a = b` compiled as `(not a) = b`: with a = 0
and b = 5, Ring answers 1, 0, 0, 1 to `not a = b`, `not a + b`, `not a < b`, `not a * b`, and Ring++ 2.0.3 answered
0, 6, 1, 5. Softanza's library has 35 such lines in 21 of its 612 files, among them the guards `if NOT len(x) > 1` and
`if NOT cResVar = ""`. The compiler now puts the parentheses where Ring puts them. The one place Ring does not apply
the rule is a line that begins with `not` and holds an `=` -- there it is an assignment -- and that still stops with a
refusal, as before.

**The checker** (`rnxc check`) no longer reports a member name as an unassigned variable, and reports a builtin's name
or a defined name read as a variable, which Ring raises R24 on.

**The figure.** The counts at https://mayouni.github.io/ringpp/how.html#parity are the ones published with 2.0.3 --
12,924 of Ring's 13,008 checks on Windows, 12,170 of 12,255 on Linux. They were not measured again for 2.0.4: the full
pass over Softanza's tests was not run on this compiler, and the 35 `not` lines may move some of its answers toward Ring's.
The gate passes, and the 162 probe programs run byte for byte as Ring runs them on Linux.

Each archive was unpacked into an empty folder and run in a clean environment on Windows and on Linux.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`.

Ring++ 2.0.2 -- three silent wrong answers fixed, and the parity figure restated with every check counted.

**`floor(a / b)` is the floor of the real quotient** (F-129). Ring++ compiled every `floor(a / b)` as integer division,
so `floor(14.15 / 1.9)` answered 14 where Ring answers 7. It now uses integer division only when both sides are proved
integers. Softanza's spectrum plot drew 154 of its 442 points before; it draws all 442 now.

**A `load` inside a block runs its file where it stands** (F-128). Ring follows a `load` written inside an `if`, a loop or
any other block: the file's functions are defined, and its top level runs each time the line is reached. Ring++ followed
top-level loads only, so such a file was never loaded at all. A missing file in such a load now refuses the program, as on
Ring.

**A class compiled on top of the library inherits its parent's initial values.** When a program is compiled on top of the
precompiled library (`rnxc prefix`), a class whose parent lives in the library started without the parent's attribute
initialisers, and the first read of one raised R24. Compiled whole it was always right.

**The parity figure, restated.** Softanza's tests write their checks as `[PASS]` or as `[OK]`, and until now only the
`[PASS]` lines were counted. That gave "8,540 of 8,540", which was true of those checks and said nothing of the 4,468
written as `[OK]`. Counting both, Ring++ 2.0.2 passes **12,863 of the 13,008 checks Ring passes on Windows (98.9%)** and
**12,170 of 12,255 on Linux (99.3%)**. Every one it does not pass has a named cause:

- 81 are in two test files that read a global without its `$` inside a function, which Ring++ refuses to compile;
- 61 depend on one 3,909-line function that does not fit in the register window (Windows);
- the rest measure time or memory, and on Linux one is a cluster test that does not finish under Ring++.

They are listed at https://mayouni.github.io/ringpp/how.html#parity.

Each archive was unpacked into an empty folder and run in a clean environment on Windows and on Linux.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`.

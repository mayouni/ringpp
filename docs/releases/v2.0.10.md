Ring++ 2.0.10 -- a shorter pause when a large admission is installed, `chdir` that waits for one, and functions named with a leading `@@`.

**A shorter pause when a background admission is installed.** In 2.0.9 an admission compiled on a thread of its own
(`admitstart`), but installing it into the running program still happened on the program's thread: for Softanza's whole
library, 114-143 ms during which the program answered nothing. Most of that work depends only on what was compiled, so it is
now done by the thread that compiled, before `admitfinish` is called: the records of the files admitted, the strings the VM
keeps, and the class tables of classes that are new to the program. What is left on the program's thread is about 10 ms of
install and the admitted code's own top level, which runs where `admitfinish` stands, as before.

Measured here, a program serving requests over HTTP while Softanza's library was admitted in the background: the longest
any request waited was 41-59 ms over nine runs, against 114-143 ms on 2.0.9. If the program changes its classes while the
compile runs -- with `addmethod` -- the prepared class tables are set aside and built at install time, as before.
`RNXC_ADMIT_PHASES=1` prints the work done on the compiling thread (`stage`) and the wait for `admitfinish` (`wait`)
apart from the install.

**`chdir()` waits for an admission compiling in the background.** The compile reads a relative `admitfile` path, and the
files the admitted code loads, against the current directory. A `chdir()` while it ran could move that directory under it.
Now `chdir()` waits for the compile to finish first, so the compile sees the directory the program had when it called
`admitstart`, as the synchronous verbs do.

**A function named with a leading `@@` is a function like any other, as on Ring.** Ring++ took every name beginning with
`@@` for one of the compiler's own functions, so `isfunction("@@")` answered 0 where Ring answers 1, `functions()` left such
functions out, and in a resident program a call compiled before such a function was admitted could not reach it once it
was (R3). Softanza defines `@@`, `@@NL`, `@@S`, `@@SP` and `@@XT`. They are found, listed and called now, as on Ring; the
compiler's own `@@main` stays unknown, as on Ring.

Everything in 2.0.9 is here unchanged. A program run with `rnxc <file>` compiles to the same code as before -- the probe
programs and the kernels byte for byte -- and runs as fast. The gate passes, the probes run as Ring runs them on Windows
(176) and on Linux (177), and the resident guard's 28 checks pass on both. Each archive was unpacked into an empty folder
and run in a clean environment on Windows and on Linux, from a third folder, with an empty cache.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`, or
`bin/rnxc resident a.ring b.ring` to run files as one program that can take more.

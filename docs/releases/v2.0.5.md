Ring++ 2.0.5 -- Softanza's main branch, built for Ring++ from its own source, and five more answers given as Ring gives them.

**The Softanza in the packages is its main branch.** Until 2.0.4 the packages carried a branch of Softanza prepared for
Ring++; main itself did not load on Ring++, because its functions read top-level names bare, which Ring++ refuses
(Ring++ asks for `$name` there). Main now spells them that way -- 1,105 reads and writes in 60 files, generated by a tool and
checked byte by byte -- and nothing else changed: 30 of Softanza's narrated tests, one per folder, print the same
output before and after on Ring 1.27 itself (695 checks each), so the change costs a program that still runs on Ring
nothing. The engine in both packages is built from main's own engine source for Ring++ (89 libraries on Windows, 87 on
Linux). And main's library loads on Linux: three of its loads named a file in another case than its own, which a
Windows disk forgives and a Linux disk does not.

**Five answers Ring gives, which 2.0.4 did not:**

- A multi-line string in a source file saved with Windows line endings (CR LF) holds LF alone, as on Ring on Windows:
  Ring opens a source file in text mode there. `"ab` / `cd` / `ef"` is 8 characters on Ring and was 10 on 2.0.4.
  On Linux Ring keeps the CR, and so does Ring++.
- `trim()` removes spaces only, as Ring's does: `len(trim(nl + tab + "a" + nl))` is 4 on Ring and was 1. It reaches
  Ring's own `endswith`, `startswith` and `split`, which trim first.
- `str2list()` drops a carriage return before each newline and makes no empty last line: `"a" + nl + "b" + nl` is two
  lines on Ring and was three.
- `x = a and b and c` as a statement is an assignment. In some contexts the grammar Ring++ parses with reads it as a
  comparison of `x = a` followed by `and b and c`, and 2.0.4 compiled that comparison, so the assignment never
  happened -- an R24 at the next read, or a stale value used without a word. Softanza's geographic features stopped on
  it: their test passed 3 of its 100 checks before the fix, and passes all 100.
- `shutdown(n)` ends the program with exit code n. It was missing (R3).

**The compiled-program cache has a size.** `rnxc` keeps each program it compiles in a cache so the next run starts at
once, and nothing ever removed an entry: on the machine these releases are made on it reached 54 GB, 5,367 programs,
and filled the disk. The least recently written entries now go once the cache passes 4 GB. `RNXC_CACHE_MB` sets
another limit, and 0 removes it.

**`rnxc migrate` lists every site.** It lists each place a top-level name is used bare inside a function, which Ring++
refuses; it missed `n++`, `add(n, v)`, `insert(n, ...)` and `del(n, i)`, so a program moving from Ring was refused again
at each of them after the others were changed. https://mayouni.github.io/ringpp/move.html is the page for that move.

**The figure.** The counts at https://mayouni.github.io/ringpp/how.html#parity are the ones published with 2.0.3 --
12,924 of Ring's 13,008 checks on Windows, 12,170 of 12,255 on Linux -- measured on the branch, not on main. They were
not measured again: the full pass over Softanza's tests was not run on this compiler, and the five fixes above are
expected to move some of its answers toward Ring's. The gate passes, the 166 probe programs run byte for byte as Ring
runs them on Windows, and 167 on Linux.

Each archive was unpacked into an empty folder and run in a clean environment on Windows and on Linux, from a third
folder, with an empty cache: a Softanza program cold and warm on both, and on Windows three of main's own tests (79,
100 and 31 checks, none failing).

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`.

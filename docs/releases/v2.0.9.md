Ring++ 2.0.9 -- admissions compiled while the program runs, programs admitted as namespaces of their own, and `rnxc check --closed`.

**An admission compiled in the background.** A resident program (`rnxc resident`) used to stop while new code compiled: a
program taking in Softanza's whole library answered nothing for the ~14 s of its compile. Now the compile can run on a
thread of its own while the program goes on:

- `admitstart(cVerb, ...)` takes one of the admission verbs -- `admitfile`, `admitcode`, `replacefile`, `replacecode`,
  `admitapp`, `replaceapp` -- and that verb's own arguments, starts the compile and answers 1.
- `admitstate()` answers "compiling", "compiled", or "" when none was started; `admitstate(nWaitMs)` waits at most that long
  first.
- `admitfinish()` waits if it must, then installs the code and runs its top level where the call stands. It is the same
  admission the verb makes: admitted, or refused with the verb's own reason.

One compiles at a time: while it does, every other admission and release raises, saying which one is compiling. A file
whose top level starts one and never finishes it leaves the program as it was, and `rnxc resident` says so.

Measured here: a program serving requests over HTTP answered about 70,000 of them while Softanza's library compiled in the
background (about 16 s). The longest wait was 114-143 ms: installing 49,000 functions into the running program and running
the library's top level, which happen on the program's own thread. A small admission through `admitstart` costs about 0.1 ms
more than the verb's own.

**A program admitted as a namespace of its own.** `admitapp(cApp, cSource, aExports)` admits code under a name. Its
functions, classes and globals are its own, so two such programs may define the same names. Its code finds its own names
first and the shared program's after, including a name nothing defines yet when its code is compiled. Another app reaches it
only through the names it exports, spelt `app.Name` -- `app.Sum(2, 3)`, `new app.Entry(...)` -- and anything not exported
raises R3 when reached. `replaceapp(cApp, cSource)` replaces code within the app. The program that admits apps reaches their
names by their full spelling `app::Name`. Refused, with the reason: an export naming nothing the app defines, an app name
that is not an identifier, and the release of an app's admission (another app may hold its exports).

**The socket waits at most as long as asked.** `rpp_http_next(nWaitMs)` waits at most nWaitMs for a request and answers -1
when none came, so a request loop with work of its own -- an admission compiling in the background -- is not held by an idle
socket. `rpp_http_next()` waits as before.

**`rnxc check --closed`** asks whether a unit DEFINES every name it uses. The default check makes Ring's claim -- an error the
moment a line runs -- and so stays silent on a library, in which nothing runs, and on a unit that calls `eval`, `loadlib` or
an admission verb. `--closed` checks those too; a file the unit cannot read or parse still silences it. Arity is checked
across the unit's files. `--natives=<file>` names native functions a library registers, one a line, and
`--subst=<file>=<text>` checks the unit with one file's text replaced, without writing it. The default `rnxc check` is
unchanged.

Fixed: a refused statement inside an app's admission named its file by an internal path.

Everything in 2.0.8 is here unchanged. A program run with `rnxc <file>` compiles to the same code as before -- the 175 probe
programs and the kernels byte for byte -- and runs as fast. The gate passes, the probes run as Ring runs them on Windows and
(176) on Linux, and the resident guard's 28 checks pass on both. Each archive was unpacked into an empty folder and run in a
clean environment on Windows and on Linux, from a third folder, with an empty cache.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`, or
`bin/rnxc resident a.ring b.ring` to run files as one program that can take more.

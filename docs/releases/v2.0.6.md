Ring++ 2.0.6 -- Softanza's max layer loads again, and six more answers given as Ring gives them.

**2.0.5 could not load Softanza's max layer.** The packages leave Softanza's test folders out, and the max layer's loader
(`max/stzMax.ring`) loads one file from them: `test/stzTestoor.ring`, Softanza's test framework. On every package before
this one, a program that loads the max layer was refused before it ran (`Can't open file test/stzTestoor.ring`). The
packages now keep any file that a loader of the library names. A program that loads only the base layer
(`stzBase.ring`, or `load "stzlib.ring"`) was never affected.

**Six answers Ring gives, which 2.0.5 did not.** Each was found by running Softanza's website examples and its two books
on Ring++, and each is checked by a program that the oracle, the official Ring 1.27 and Ring++ print the same way:

- `%` on a number with a fraction is C's `fmod`, as on Ring: `7 % 2.5` is 2 (2.0.5 said 1, without an error),
  `2.07 % 0.39` is 0.12 (2.0.5 stopped with "Can't divide by zero"), and `x %= 2.5` compiles. Ring's own `gcd` and `lcm`
  on fractions reach it.
- `dec()` reads a hexadecimal string as Ring's does (C's `sscanf`): `dec("0x41")` is 65, `dec("  ff")` 255, `dec("12zz")`
  18, and a string with no hexadecimal digit raises E7. 2.0.5 answered 0 to all of them.
- Inside a brace on an object that a function returned -- `StzCalendarQ([2024, 10]) { ? len(WorkingDays()) }` -- a bare
  call to a builtin such as `len` or `upper` is the object's method when it has one and the builtin otherwise. 2.0.5
  stopped with "Calling Function without definition: len".
- Inside such a brace, a name assigned that the object does not have becomes a variable -- the program's global at the
  top level, the function's local inside a function -- as on Ring: `KQ() { aR = Make() }` then `? len(aR)`. 2.0.5 raised
  "property not found". A name that some class of the program declares as an attribute is still the object's.
- Inside a brace, a bare call is typed as the object's method, not as a global function of the same name: with a global
  `Check()` answering a string and the object's `Check()` a list, `o { ? len(Check()) }` is 3. 2.0.5 stopped with "Bad
  parameter type!".
- A line that Ring evaluates and drops runs: `"good" + "ly" = "goodly"` (a comparison, since a literal stands before the
  `=`), a list, a number or a subscript on a line of its own. 2.0.5 refused such a line, which stopped the program there.

**Faster to start, when you ask.** A program that loads Softanza compiles the whole library the first time it runs (15 to
40 seconds), then starts from its compiled image. `rnxc prefix <library.ring>` compiles a library once and keeps it, so
every new program that loads it starts in about a second: run it once after unpacking, in `bin/load` for
`stzlib.ring`, and in `libraries/stzlib/base` and `libraries/stzlib/max` for the two layers.

**The figure.** The counts at https://mayouni.github.io/ringpp/how.html#parity are still the ones published with 2.0.3,
measured on a branch of Softanza; the full pass was not run again. The gate passes, and the 173 probe programs run byte
for byte as Ring runs them on Windows, and 174 on Linux. Softanza's website was re-run on this compiler against
Softanza's main branch, every output compared with the run on Ring it replaces, and its two books run on it.

Each archive was unpacked into an empty folder and run in a clean environment on Windows and on Linux, from a third
folder, with an empty cache.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`.

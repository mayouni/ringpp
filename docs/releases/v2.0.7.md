Ring++ 2.0.7 -- Ring's VM reflection: `ringvm_classesList()`, `ringvm_cfunctionsList()` and `cfunctions()`.

**Three functions Ring has, which 2.0.6 did not** (each answered "Calling Function without definition"):

- `ringvm_classesList()` answers a row per class, as Ring's does: its name, a position, its parent's name (`""` for none),
  its methods (each `[name, position, file, private]`), 0, and the package. Names are lower-cased. Where Ring gives
  bytecode addresses Ring++ gives the class's number and the method's entry, and privacy, which Ring++ does not keep,
  reads 0. `ParentOf` written over it answers as on Ring: `stzListXT`'s parent is `stzlist`.
- `ringvm_cfunctionsList()` and `cfunctions()` answer the name of every C function the runtime registered: the core names
  Ring 1.27 registers, then every function a library registered -- Softanza's engine and zip among them. A program that
  counts the engine's functions through it gets the engine's own count: 2,843 with the Windows package's engine, 2,787
  with the Linux one, which lacks two of the engine's domains (the GUI and the window).

Found by the Softanza book, whose chapter on the engine counts the classes of each layer, reads each class's parent and
counts the engine's functions through these calls; every block of the book keeps its promise on this release.

Everything in 2.0.6 is here unchanged. The gate passes, and the 174 probe programs run byte for byte as Ring runs them on
Windows, and 175 on Linux. Each archive was unpacked into an empty folder and run in a clean environment on Windows and on
Linux, from a third folder, with an empty cache.

Unpack anywhere -- the Windows zip, or on Linux `tar -xzf ringpp-linux-x64.tar.gz` -- and run `bin/rnxc program.ring`.

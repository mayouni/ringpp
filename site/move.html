Moving from Ring

A Ring program runs on Ring++ as it is, or it is refused with a reason. This page lists what a program may need to change. It is short: Softanza is about 300,000 lines, and the whole of its move was one rule.

1. The command

# Ring
ring program.ring

# Ring++, with the same arguments after it
rnxc program.ring

Ring's standard library is in the package and loads as it does on Ring: load "stdlibcore.ring". load "stdlib.ring" also loads Ring's extensions written in C, which Ring++ does not run (section 4), so the program is refused at that line; write stdlibcore.ring.

2. The one rule: a global used in a function is $name

On Ring, a function that assigns a name which also exists at the top of the program writes that global, without a word. Ring++ keeps the global and the local apart by their spelling: $name is a global, @name an attribute, a bare name a local. A bare top-level name used inside a function is refused, at the line, with its reason:

nCount = 0
? Bump()

func Bump
    nCount++
    return nCount
# Ring 1.27 prints
1

# Ring++ prints
Line 5 Ring++ refused this statement (identifier `nCount`, line 5 of a.ring) and did not compile it -- running past it would give a wrong answer
In function bump() in file a.ring

Written $nCount in all three places, it prints 1 on both: $nCount is an ordinary name to Ring, so the program stays a Ring program. rnxc migrate program.ring lists every such use inside a function — the file, the byte where the name starts, the name — for the program and every file it loads; the name's own lines at the top of the program take the $ with them. Softanza's main branch took 1,105 of them in 60 files, and 30 of its tests print the same on Ring 1.27 before and after.

3. What Ring++ answers differently, on purpose

A few of Ring's behaviours are defects no correct program relies on, and Ring++ answers them the other way. Each is a decision on record, with what it costs, in CORRECTIONS.md. Those a program is most likely to meet:

  • Reading a missing key of a hash list does not add it. On Ring, aHash[:x] inserts :x when it is not there.
  • A numeric for reads its bound once. On Ring a body that grows the list its len() bound measures walks the new items too; on Ring++ it stops at the length the loop began with. A loop whose limit moves is a while on both.
  • Assigning to a parameter rebinds the parameter. On Ring, p = [9] inside a function rewrites the list the caller passed. On Ring++ every write through the parameter — p[1] = 9, add(p, 9) — reaches the caller, as on Ring, and an assignment to it does not.
  • An exact tie rounds to even when a number is printed with fewer decimals: IEEE's rule, where Ring's official build rounds away from zero.

4. What Ring++ does not run, and says so

Each of these stops the program where it stands, with an error naming the call or a refusal naming the line. None of them runs on with a different answer.

  • Ring's extensions written in C — RingQt, RingLibCurl, RingOpenSSL and the rest. They call into Ring's own VM, so no other VM can host them; loadlib() on one is an error (R38, or R46). Softanza's engine is where Ring++ programs get strings and Unicode, regular expressions, HTTP, files, graphs, graphics and sound.
  • Packages (package, import), the commands that change Ring's syntax (ChangeRingKeyword, ChangeRingOperator, LoadSyntax), Ring's implicit files (ringsyntax.ring, startup.ring, ring.ring), and assigning NULL, TRUE or FALSE.
  • Raw pointers (varptr, memcpy, getptr and their family), and the VM inside the VM (ring_state_*, ringvm_*).
  • A function or a class defined inside eval(). An eval that computes, assigns or calls runs as on Ring, in its caller's scope.

5. Before it runs

# every statement of the program and of what it loads: what compiles, what is refused, and why
rnxc census program.ring

# the sites of section 2
rnxc migrate program.ring

# what Ring would only find when the line runs: an undefined function, an unknown class
rnxc check program.ring

And when a question is about what Ring itself does, Ring 1.27 is in the repository, built from its own source: it is the reference every answer of Ring++ is measured against, and it is never shipped.

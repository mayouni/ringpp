The CLI — one binary, no compiler

ringpp check finds dormant bugs before you run them. ringpp build packages a program into bytecode plus a runtime stub — no C compiler asked of you, ever, on any of five platforms.

The thesis, made concrete

Ring passes lists by reference and strings by copy. A helper that takes a large buffer as a plain string copies the whole thing onto the VM stack — on every call — before its first line runs. Same task, same loop, the only thing that changes is what you hold.

1,500 calls to a helper that reads one byte out of a 1 MB buffer. The helper looks cheap — it reads one byte. The cost is not in the function; it is in the act of calling it.

Raw Ring copies on every call 
func RawWay cData, nCalls, nSize
    # cData is a STRING parameter -- the whole
    # megabyte is copied onto the VM stack, every call.
    nSum = 0
    for i = 1 to nCalls
        nSum += ByteAtRaw(cData, (i * 7919) % (nSize - 1))
    next
    return nSum
Ring++ nothing is copied 
func RppWay oBuf, nCalls, nSize
    # oBuf is an OBJECT, and an object is a list --
    # it crosses the call boundary by REFERENCE.
    nSum = 0
    for i = 1 to nCalls
        nSum += ByteAtRpp(oBuf, (i * 7919) % (nSize - 1))
    next
    return nSum

Honest limits

A packaged program is a stub-plus-bytecode pair, not a single self-modifying file — Ring's own runtime does not look for a same-named bytecode file, and that was measured before it was assumed. Bare-metal microcontrollers are out of scope entirely: a Ring VM does not fit an ESP32-class device, and no packaging tool changes that. Where Ring++'s own library loses to plain Ring, the examples say so before they say anything else — the Qt refusal has its own page, because it deserves more than one line.

Standing on named shoulders

Ring++ vendors nothing at a user's install time, but two dependencies are compiled into the CLI itself and their authors deserve their names here: Mahmoud Fayed and the Ring team's Ring language — the design this whole project is built on, not around; and Youssef Saeed's tree-sitter-ring grammar, which every ringpp check is running. Adopted because it independently reached the same reading of Ring's type annotations that Ring++'s own measurements did. Grammar findings go back to him as issues, never patches around him — and when this project reported one defect, his fix turned out to close two. Built with Andrew Kelley and the Zig team's Zig, which compiles the whole CLI into one binary per platform.

One thesis, three siblings

Ring++ is one of several Ring foundations from the same author, each standing alone and each dependency-free except for what it names and vendors itself. What running Ring++ against all three actually found — real code, and two mistakes in Ring++'s own published claims, caught along the way.

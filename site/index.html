The CLI — one binary, no compiler

ringpp check finds dormant bugs before you run them. ringpp build packages a program into bytecode plus a runtime stub — no C compiler asked of you, ever, on any of five platforms.

The bug it found in Ring's own standard library

Not a synthetic example — this is libraries/stdlib/stdsecurity.ring, shipped in Ring 1.27, found by running ringpp check against Ring's own source tree and confirmed by actually calling the function.

encrypt_ex calls the three-parameter std_encrypt with four arguments. It has never worked — nothing in Ring's own codebase ever called it, and nothing static was looking until now.

The thesis, in one line

Ring passes lists by reference and strings by copy. That one asymmetry is behind almost everything slow about large-data work in Ring — and Ring++ does not exist because pointers are fast. On most work they lose, measurably, 3–28×, because every crossing from Ring into a native function costs real time. It exists because a Ring string is copied every time it crosses a call boundary, and a list is not — and everything Ring++ honestly offers is a way of not paying that cost where it is real, and staying out of the way where it is not.

Honest limits

A packaged program is a stub-plus-bytecode pair, not a single self-modifying file — Ring's own runtime does not look for a same-named bytecode file, and that was measured before it was assumed. Bare-metal microcontrollers are out of scope entirely: a Ring VM does not fit an ESP32-class device, and no packaging tool changes that. Ring's Qt bridge is out of scope by the same standing rule that keeps every Softanza Ring foundation dependency-free except what it vendors and supports itself. Where Ring++'s own library loses to plain Ring, the examples say so before they say anything else.

Standing on named shoulders

Ring++ vendors nothing at a user's install time, but two dependencies are compiled into the CLI itself and their authors deserve their names here: Mahmoud Fayed and the Ring team's Ring language — the design this whole project is built on, not around; and Youssef Saeed's tree-sitter-ring grammar, which every ringpp check is running. Adopted because it independently reached the same reading of Ring's type annotations that Ring++'s own measurements did. Grammar findings go back to him as issues, never patches around him — and when this project reported one defect, his fix turned out to close two. Built with Andrew Kelley and the Zig team's Zig, which compiles the whole CLI into one binary per platform.
